# ESG 重構與驗證

在專案根目錄的 Visual Studio Developer PowerShell 執行 `./tests/Test-Esg.ps1`。
前端測試也能單獨執行：`node tests/esg-calculation.test.cjs`。

- `ESGController` 負責查詢條件檢查、頁面模型和資料庫連線生命週期。
- `EsgCalculationService` 按 14 種類別查詢，共用兩套交通帳務來源的合併邏輯。
- `SGS_Calculate.cshtml` 保留查詢表單，報表分成 `_Results*.cshtml`；Vue 計算位於 `Scripts/esg-calculation.js`。
- 查詢採唯讀模式；日期欄位以年度起迄篩選。預設年份為去年，最低為 2024；搜尋類別、廠區與處理方式均有預設值。
- 搜尋移除滅火器內含物、水表口徑：滅火器依廠區及年份列出所有內含物，水費依廠區及年份查詢，依實際水表口徑分列合計。
- 頁面不顯示 header；獨立樣式位於 `css/esg-calculation.css`，表格採淺綠底黑字。
- 通勤同年度同名稱出現不同係數時會顯示錯誤；公務車或柴油缺少年度係數時也不再產生誤導的零排放。
- 保留 WD40 的 `Status == 0`、冷媒 GWP 1526 / 1908 / 2256、運輸距離與原始換算公式。廢棄物單筆結果原本除以 1000，現在標示為 tonCO₂e，與總和一致。

測試涵蓋 MVC 初始頁、錯誤年份與類別、跨文化小數解析、缺少係數與零係數、公務車多氣體加總，以及前端係數比對和換算。這些測試不連接正式資料庫。Razor 可在排除 `obj` 目錄的暫存站台以 ASP.NET Compiler 預編譯驗證。

尚須以實際資料核對的業務規則：WD40 的年份儲存格式（目前仍沿用 Contains）、電力上游僅統計南科廠、冷媒資料表沒有年度欄位、以及既有各類係數的單位。重構未另行改定這些規則。

預設類別為冷媒，四類廠區與交通／廢棄物處理方式預設為全部。報表保留各廠區與種類明細並顯示合計；交通每列使用個別係數，缺少任一係數時總排放量顯示資料不完整。
交通「全部」效能修正：改用交通專用 LINQ 查詢，於資料庫端限定年份及七種交通方式後才彙總，避免先統計所有帳務。ACPTA／ACPTB 以原始複合鍵等值關聯，不在關聯欄位呼叫 Trim；其他帳務類別沿用既有查詢。`TrafficQueryTests` 驗證年份、方式、單頭關聯、加總，以及 EF 查詢轉換，未調整逾時設定、SQL 檔案、資料庫結構或索引。
員工通勤係數改為讀取 `SGS_ParameterSetting` 中 `PAR002 = 通勤` 且 `Year = 查詢年份` 的設定，以 `PAR004` 配對員工交通方式，再由 `PAR001` 連結啟用的 `SGS_Parameter.PAR000`，取 `SGS_Parameter.PAR002` 作為係數。不再查詢 `BRM_MST_EMISSION_FACTOR`；係數缺少、非數字或同方式存在不同係數時會顯示設定錯誤，避免漏列通勤排放。已增加來源篩選、欄位配對、小數解析、零值及異常設定的回歸測試。

員工通勤查詢於彙總前排除 `GHG_MST_COMMUTE.TRANSPORTATION = 公務車`，因此不列入通勤明細、係數配對或排放合計；獨立公務車計算不受影響。
